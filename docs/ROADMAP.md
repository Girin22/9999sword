# 개발 로드맵 — Codex용

목표: **M3까지 도달하면 "플레이 가능한 게임 루프"**. 그 뒤는 여유가 있는 만큼. 각 마일스톤은 "완료 조건"을 전부 만족해야 끝난다. 완료 조건은 가능한 한 vitest로 자동 검증한다.

규칙: 수치는 전부 `data/*.json`에서. 전투 로직은 `src/sim/`(Phaser 무의존). 에셋 없으면 도형 플레이스홀더. UI 레이아웃은 `docs/UI_LAYOUT.md`의 좌표(유저 목업 확정)를 `src/ui/layout.ts`에 그대로 옮긴다.

---

- [ ] `npm create vite` (vanilla-ts) + `phaser` + `vitest` + eslint/prettier
- [ ] `src/config.ts`: 1080×1920, `Phaser.Scale.FIT`, `autoCenter: CENTER_BOTH`, 배경색 종이색
- [ ] `src/data/`: `data/*.json` import + TS 타입(`docs/MANIFEST.md` 스키마)
- [ ] 씬 뼈대: Boot → Title → Lobby → Formation → Battle(+BattleHUD) → Result. 각 씬은 제목 텍스트 + "다음" 버튼만
- [ ] `src/sim/rng.ts`: 시드 가능한 RNG (테스트 재현용)

**완료 조건**: `npm run dev`로 세로 캔버스가 뜨고 씬 5개를 버튼으로 순환. `npm run test` 통과(빈 테스트 1개). `npm run build` 성공.

## M1 — 대장간: 강화 루프 (sim)

`src/sim/forge.ts`

- [ ] `ForgeState { n, kind, trait, clicksTotal, shapeCounter(0..4), spiritCounter(0..9) }`
- [ ] `enhance(state, rng, growth)`: 비용 차감 → 결과 롤(실패/+1/+2, 대장간 Lv 반영, 1회 강화량 g 곱) → 클릭 카운터 증가(실패 포함) → 5클릭마다 종류 굴림 → 장인의 기운 롤(1.27%, 10회 무발동 시 11번째 확정) → 발동 시 질서/혼돈 50:50, 티어 분포, 풀에서 특성 선택, 슬롯 덮어쓰기 → 나 강림 3%
- [ ] 부가 옵션 줄: 5클릭 굴림 시 `options.json` 풀에서 한 줄(추가/교체), 줄 수 상한 `save.lines`(시작 2)
- [ ] `atk(n)` 공식, 돌파 플래그(n이 10의 배수에 처음 도달)
- [ ] 튜토리얼 보정 훅(S1: 첫 3클릭 확정, 8~10클릭 혈검 확정)
- [ ] 테스트: 10,000회 시뮬에서 실패율 ≈ 20%, 장인의 기운 "10회 안 발동 ≈ 12%", 11번째 100%, 5클릭마다 kind 변경 이벤트, 특성 슬롯 1개 유지

**완료 조건**: 테스트 통과. Battle 씬에 강화 버튼 하나 + 텍스트로 `+N · 종류 · 특성 · 게이지 5/10`가 갱신된다.

## M2 — 병사·검·보급·기절 (sim)

`src/sim/units.ts`, `supply.ts`, `barracks.ts`

- [ ] `Unit { def, hp, maxHp, sword: SwordInstance | SCRAP, state: 'fight'|'stunned'|'returning'|'resting'|'mining'|'avatar', pos, stunTimer, orderStacks }`
- [ ] `SwordInstance { n, kind, trait, stacks }`; 검에서 파생되는 공격력·공속·이속·사거리·타격수 계산(`swordStats(sword, unit)` — 무게·적합도·종류 고유 옵션·유닛 고유 옵션 반영)
- [ ] 보급: 병종 선택 → 그 병종 전원 `returning` → 막사 도착 시 검 교체(각인 계승 판정) → 재출격. 대장간 리셋(+0, 기본검, shapeCounter 0, spiritCounter 유지)
- [ ] 기절: hp 0 → `stunned`, 검 → SCRAP(atk 12), 쿨타임 후 `fight` 그 자리
- [ ] 회복: 20% 이하 중 최저 1명 → `returning` → 침상 `resting`(쿨타임 절반) → 재출격. 침상 수 제한, 자동 호출 없음
- [ ] 광산: 배치 유닛 1명 `mining`, 생산 tick. 보급 시 광부도 왕복
- [ ] 테스트: 보급 후 병종만 교체·다른 병종 유지 / 각인 계승 / 기절 시 중첩·특성 소실 / 회복 버튼 잠금 / 광산 생산 = 기본×인원×(1+0.05N)

**완료 조건**: Battle 씬에서 도형 병사들이 서 있고, 병종 버튼으로 보급하면 걸어와서 검(사각형)이 바뀐다. 회복 버튼 동작. 광산에 1명 서 있다.

## M3 — 전투·웨이브·성벽 → 플레이 가능 ★

`src/sim/combat.ts`, `wave.ts`, `monsters.ts`

- [ ] 몬스터 8종 생성·이동·타겟팅(잡몹: 가장 가까운 병사, 하르피: 가장 뒤, 거대: 성벽 향해 직진하며 막는 병사 공격, 헤파이스토스: +N 최고 우선)
- [ ] 병사 타겟팅(기사: 가장 가까운 적 / 투검사: 사거리 안 가장 가까운 / 마검사: 아군 밀집 지점 이동 + 깃발 원 버프·디버프 / 거대 등장 시 거대 우선)
- [ ] 피해 공식 4층(방어 → 배율 → 방어 무시 → 피해 감소), 치명타, 타격 수, 관통(직선), 광역(부채꼴)
- [ ] **전투 연출 트윈**(`docs/ART_STYLE.md` §3): 근접 부딪침(돌진 60%·포개짐 8~12px·복귀 30%), 투검사 투척→구르기, 마검사 순회+깃발 펄스, 피격 튕김+플래시, 기절 눕기. 플레이스홀더 도형에도 적용 — 이게 게임 손맛이라 M3에 포함
- [ ] 웨이브 타임라인: 잡몹 40초 생성 → 경고(10초/헤르메스 5초, 생성 정지) → 거대 등장 → 격파 시 다음 웨이브, 성벽 30% 회복 → 마지막 = 보스
- [ ] 성벽: 잡몹은 안 때림. 거대 몬스터 성벽 DPS = 내구도 ÷ `wallSeconds`. 0 = 실패
- [ ] 드롭 재료 → 병사가 들고 있다가 귀환 시 합산(단순화 허용: 즉시 합산)
- [ ] 스테이지 배율 적용(`stages.json`)
- [ ] 특성 **시작 4개 + 혈검** 효과 구현(단련·숨고르기·혈검·둔검). 나머지 특성은 M5
- [ ] 클리어/실패 판정 → Result 씬
- [ ] 테스트: 헤드리스로 S1 전체를 시드 고정 시뮬 — "아무 조작 안 하면 실패", "매 5초 강화+보급 스크립트면 클리어" 두 시나리오

**완료 조건**: 브라우저에서 S1을 처음부터 끝까지 플레이해 클리어/실패 화면을 본다. 배속 ×2 동작. 이 시점에 첫 플레이 테스트를 사람이 한다.

## M4 — 아웃게임: 로비·편성·성장·저장

- [ ] `save.ts`: localStorage 단일 키, 스키마 버전, 초기화(경고+재확인)
- [ ] 로비: S1/S2/S3/무한 선택(잠금 표시), 각 스테이지의 식량 제한·레시피 목록(보유 체크/실루엣), 상점, 보유 레시피
- [ ] 편성: 해금 유닛 카드, 식량 합계/제한, 광부 선택 화면(최저 식량 기본)
- [ ] 결산: 보스 드롭(재화 고정+랜덤, 레시피 60% — 특성/옵션/모루 3종 혼합), 실패 시 웨이브당 고정분, 카드 표시, 연대기 템플릿 1개
- [ ] 상점 구매 → `growth.json` 효과 적용(1회 강화량·야금술·유닛 기본 수치(유닛별)·침상·기절 쿨·광산 슬롯·성벽·장인의 기억·대장간 성향). `future.avatars/relics`는 저장 스키마 자리만
- [ ] 유닛 해금(S1/S2/S3 클리어), 무한 모드 해금·회차 배율
- [ ] 햄버거: 배속·사운드 on/off·초기화·크레딧

**완료 조건**: S1 클리어 → 재화 받고 → 상점에서 대장간 Lv2 구매 → S2 진입 → 레시피 드롭 → 풀에 반영. 새로고침해도 유지. 초기화 동작.

## 우선순위 메모

- 시간이 없으면 **M3 → M4 순으로 끝내고 M5는 시작 특성 4개 + 나 강림만**. 나머지 특성은 JSON에 있되 "미구현" 플래그로 풀에서 제외.
- M6는 에셋이 오기 전엔 건너뛴다. 플레이스홀더 상태로도 게임성은 검증된다.
- 밸런스는 M3 완료 후 사람이 플레이하며 `data/*.json`만 고친다. 코드는 건드리지 않는다.
